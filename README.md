# Ya-Ma

<img src="plugins/yandex-mail/assets/ya-ma.png" alt="Конверт Ya-Ma с карточкой .msg" width="144">

Неофициальный плагин для личной Яндекс Почты и доменных ящиков Яндекс 360. Агент может разобрать переписку, найти вложение, поставить метки, подготовить ответ или проверить новые письма по расписанию. У каждого подключённого ящика свой режим доступа.

## Установка из репозитория GitHub

Ya-Ma устанавливается из публичного репозитория в Codex, Claude Code и OpenClaw. Для OpenClaw начните с раздела установки полного плагина ниже. Для других клиентов сначала установите команду Ya-Ma. [Репозиторий Ya-Ma](https://github.com/grebennikovxyz/ya-mail-plugin)

### 1. Установите команду ya-mail и подключите ящик

Потребуются Git и uv. Выполните команды под пользователем, от которого запускается клиент. Полный пакет OpenClaw сам готовит окружение при первом запуске. [Установка uv](https://docs.astral.sh/uv/getting-started/installation/)

```sh
uv tool install --python 3.13 git+https://github.com/grebennikovxyz/ya-mail-plugin.git@main
uv tool update-shell
```

Откройте новый терминал и запустите мастер. Он подскажет, где создать пароль приложения в Яндекс ID, и предложит выбрать права для этого ящика.

```sh
ya-mail connect
ya-mail status
```

### 2. Добавьте Ya-Ma в свой клиент

**Codex** использует каталог `grebennikov-mail`.

```sh
codex plugin marketplace add grebennikovxyz/ya-mail-plugin --ref main
codex plugin add yandex-mail@grebennikov-mail
codex plugin list --marketplace grebennikov-mail
```

**Claude Code** использует каталог `grebennikov-ya-mail`.

```sh
claude plugin marketplace add grebennikovxyz/ya-mail-plugin
claude plugin install yandex-mail@grebennikov-ya-mail
claude plugin list
```

**OpenClaw** читает каталог Claude из того же репозитория. Первая команда показывает карточку Ya-Ma. При установке `--force` подтверждает выбор источника GitHub и позволяет заменить существующую копию, а `--accept-capabilities` разрешает заявленные возможности MCP.

```sh
openclaw plugins marketplace list grebennikovxyz/ya-mail-plugin
openclaw plugins install yandex-mail --marketplace grebennikovxyz/ya-mail-plugin --force --accept-capabilities
openclaw plugins inspect yandex-mail
```

Попросите в личном чате «Покажи подключённые ящики Яндекс Почты». При первой установке ответом будет пустой список. Затем напишите «Подключи мой ящик» и откройте предложенную форму. [Настройка формы для Telegram и удалённого Gateway](#подключение-из-чата)

## Установка из ClawHub для OpenClaw

Выполните под пользователем Gateway. При первом запуске Ya-Ma установит собственное окружение Python 3.13 из исходников внутри плагина. Для этого нужны интернет и Node.js из установки OpenClaw. На Linux, macOS и Windows x64/arm64 при отсутствии uv плагин скачает закреплённую сборку Astral и сверит SHA-256. Последующие запуски используют сохранённый абсолютный путь. [Плагин в ClawHub](https://clawhub.ai/grebennikovxyz/plugins/yandex-mail)

```sh
openclaw plugins install clawhub:@grebennikovxyz/yandex-mail --accept-capabilities
```

Проверка через работающий Gateway:

```sh
openclaw gateway call tools.invoke --params '{"name":"yandex-mail__list_accounts","args":{}}' --json
```


Если MCP-сервер `yandex-mail` уже подключён вручную, можно добавить только навык. В каталоге рабочего пространства OpenClaw выполните команду ниже. Для неё нужен CLI `clawhub`, который устанавливается командой `npm install -g clawhub`. [Навык Ya-Ma в ClawHub](https://clawhub.ai/grebennikovxyz/skills/ya-ma)

```sh
clawhub install @grebennikovxyz/ya-ma
```

## Другие способы установки

**OpenClaw из релиза GitHub.** Скачайте архив с окончанием `-clawhub.tgz` и передайте его путь команде `openclaw plugins install` с флагами `--force --accept-capabilities`. [Архивы последнего релиза](https://github.com/grebennikovxyz/ya-mail-plugin/releases/latest)

В клиенте с ручной настройкой MCP выберите транспорт **stdio**, команду `ya-mail` и аргумент `serve`. В клиенте с импортом ZIP можно импортировать архив плагина после установки команды `ya-mail`.

Для Windows x64 доступна автономная сборка. Скачайте архив с окончанием `-windows-x64.zip`, распакуйте и запустите `connect.cmd`. В архив входят Python и библиотеки. Импортируйте ZIP в поддерживающий это клиент. Для ручного добавления MCP укажите полный путь к `runtime/python.exe` из распакованного архива и аргументы `-I -B -m ya_mail.cli serve`. [Сборки для скачивания](https://github.com/grebennikovxyz/ya-mail-plugin/releases)

## Подключение из чата

1. Напишите в личном чате «Подключи ящик anna@example.org». Для браузера на самом компьютере Gateway уточните «открою на этом компьютере».
2. Откройте ссылку из ответа агента. На странице будут адрес ящика, ссылки на настройки IMAP и создание пароля приложения типа «Почта». Выберите права. Пароль Яндекс показывает один раз. Он действует до отзыва.
3. Если Gateway удалён, браузер зашифрует пароль открытым ключом этой установки. Верните код `YM1.…` в тот же личный чат в течение 10 минут. Ya-Ma проверит вход в Яндекс и подтвердит адрес и права. После использования или истечения срока нужен новый код.

Этот способ работает с телефона и за NAT. Страница проекта на GitHub Pages выполняет шифрование в браузере. Адрес и открытый ключ передаются во фрагменте ссылки. У страницы нет сетевых запросов для отправки пароля. Расшифровка и подключение к IMAP/SMTP происходят на компьютере владельца. В Linux без Secret Service владелец может явно выбрать хранение с локальным ключом в личном каталоге службы. Пользователь ОС, под которым работает служба, и администратор имеют доступ к этому ключу. По умолчанию используется системное хранилище паролей.

**Временная форма на своём Gateway.** На том же компьютере попросите «открою на этом компьютере». Для удалённых устройств администратор при желании может один раз настроить собственный HTTPS-маршрут вместо обмена зашифрованным кодом. Проксируйте только путь `/ya-ma/connect/` на `http://127.0.0.1:8776/ya-ma/connect/` на хосте Ya-Ma, сохраняя внешний заголовок `Host`. Отключите запись тела HTTP-запросов. Мастер слушает loopback до первого успешного подключения или 10 минут. В этой форме пользователь вводит одноразовый код из чата. После подтверждения попросите агента показать ящики.

Сохраните HTTPS-адрес под пользователем Gateway. Из каталога установленного расширения в Unix:

```sh
YA_MAIL_BIN="$(node ./launch.mjs prepare)"
"$YA_MAIL_BIN" setup-origin https://mail-setup.example.org
```

Замените домен адресом своего защищённого маршрута. Без своего HTTPS-адреса используется зашифрованный код. На локальном компьютере можно открыть мастер из чата через loopback.

## Мастер подключения

1. Нажмите **Открыть настройки Почты**. Выберите нужный ящик, включите IMAP и способ входа «Пароли приложений и OAuth-токены». Сохраните настройки. [Почтовые программы](https://mail.yandex.ru/#setup/client)
2. Нажмите **Открыть Яндекс ID**. У того же аккаунта выберите тип приложения **Почта**, введите название, например «Ya-Ma для Codex», и нажмите **Далее**. Скопируйте сгенерированный пароль. Яндекс показывает его один раз. Он продолжает работать до отзыва, в том числе во время запусков по расписанию. [Пароли приложений](https://id.yandex.ru/security/app-passwords)
3. Введите полный адрес ящика и вставьте пароль в скрытое поле мастера. Выберите **Только чтение**, **Чтение, метки, папки и черновики** или **Также разрешить отправку писем**. Мастер проверит IMAP, а для режима отправки также выполнит вход по SMTP. После успешной проверки пароль сохранится в Windows Credential Manager, macOS Keychain или Linux Secret Service. Эти режимы ограничивают инструменты плагина. Права самого пароля задаёт Яндекс.
4. Команда `ya-mail status` покажет сохранённый ящик и его режим. Чтобы проверить соединение с Яндексом, выполните `ya-mail check адрес@домен`. Команда покажет число папок и непрочитанных писем. Попросите в чате «Покажи пять последних писем в папке INBOX ящика …». Повторите мастер для дополнительного адреса или смены режима.

На Windows из распакованного исходного проекта мастер также открывается файлом `connect.cmd`. Для терминала без графической оболочки есть `ya-mail connect --terminal`. Если вход отклонён, проверьте тип пароля, адрес, настройки IMAP и ограничения администратора домена. [Справка Яндекса](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others)

## Мои ящики

Подключите каждый адрес через `ya-mail connect`. Попросите «Назови orders@example.org „Работа“ и покажи сводку по моим ящикам». У каждого раздела есть полный адрес получившего ящика, внутри письма сгруппированы по папкам Яндекса. Это работает и для скрытой копии. Фильтры Яндекса продолжают раскладывать письма на сервере.

| Команда в чате | Что сделает Ya-Ma |
| --- | --- |
| «Покажи настройки папок рабочего ящика» | Покажет режим каждой папки и какие настройки унаследованы. |
| «Поставь Заказы в приоритет» | Покажет Заказы и вложенные папки первыми. Обычные папки тоже получают свою очередь. |
| «Пропускай Рассылки» | Исключит ветку из сводок и расписаний. По прямой просьбе её можно открыть. |
| «Запрети доступ к Кадрам» | Закроет ветку для чтения, поиска, вложений и изменений. Для снятия запрета Codex запросит подтверждение в чате. |
| «Ответь на это письмо» | Подготовит черновик в получившем ящике, покажет отправителя, адресатов и тему. Адрес для ответа берётся из Reply-To либо From. |
| «Ответь на это письмо с sales@example.org» | Сохранит черновик в другом подключённом ящике со ссылкой на исходную переписку. По команде отправки использует SMTP выбранного ящика. |

По умолчанию в обзор входят Входящие и пользовательские папки. Спам, Корзина, Отправленные, Черновики и Архив пропускаются. Настройка дочерней папки может изменить унаследованный приоритет или пропуск. Полный запрет родителя действует на всю ветку. Если закрытая папка исчезла после переименования, обработка этого ящика приостанавливается. Поставьте запрет на новый путь и снимите старое правило. Остальные ящики продолжают работать.

Для общей задачи выберите ящики и при необходимости перечислите папки для каждого. Инструмент `poll_mailboxes` выдаёт отдельный пакет и подтверждение на каждую папку, включая папки сортировки. Если один ящик недоступен, сводка покажет ошибку этого ящика. Первая проверка начинает с текущей позиции, а для папок, созданных после её запуска, захватывается и первое доставленное письмо. При обновлении сохраняются подключения, позиции и неподтверждённые пакеты. Для прежней задачи в пропускаемой системной папке включите эту папку вручную.


## Ленивый разбор накопившейся почты

Мастер `ya-mail lazy setup --account user@example.org` показывает примеры из выбранного ящика. По умолчанию выбраны Входящие. С согласия владельца мастер проверяет заголовки Отправленных и предлагает защитить адреса людей, с которыми были двусторонние переписки, прекратившиеся более трёх лет назад. Защищённые адреса и выбранные рассылки сохраняются в локальных правилах ящика и читаемом файле SKILL.md. Перед сохранением мастер показывает предварительные решения.

Разбор начинает с самых старых непрочитанных писем старше одного календарного года. Личные переписки, отмеченные письма и письма с непроверенной историей остаются на месте. Счета, важные изменения и сомнительные сообщения переходят в папку «На согласование». Реклама одобренных рассылок попадает в список кандидатов на удаление. Команда «Покажи дайджест и предложи удалить рекламу» открывает список и форму с точными письмами. После подтверждения Ya-Ma снова проверяет права, непрочитанность и защиту переписки.

Для автоматического запуска укажите в мастере сокет рабочего Codex App Server и ID чата на этом сервере. Диагностика доступна командой `ya-mail lazy doctor --account user@example.org`. При свежей телеметрии, 15 минутах простоя и менее чем часе до сброса короткого лимита запускаются до трёх обработчиков. Новая задача прерывает классификацию. Остаток в конце окна составляет не менее 10% исходного по оценке телеметрии, с запасом на незавершённые запросы. По умолчанию действует также предел в один процентный пункт недельной квоты. Исходные значения сохраняются после перезапуска. Без наблюдаемого рабочего чата или данных о лимитах остаётся ручной режим.

```sh
ya-mail lazy preview --account user@example.org --limit 8
ya-mail lazy run --account user@example.org --max-messages 12 --token-budget 12000
ya-mail lazy digest --account user@example.org
ya-mail lazy disable --account user@example.org
```

Ручной запуск через MCP использует sampling клиента при наличии поддержки либо локальный Codex CLI. Классификатор получает отобранный текст рассылки. По окончании доступен постраничный дайджест с причинами решений.

## Подключение с телефона, OpenClaw и n8n

- **Телефон.** `ya-mail connect --web` откроет мастер на хосте по адресу `http://127.0.0.1:8776`. Для подключения с телефона пробросьте этот порт своим SSH-клиентом на loopback телефона. Откройте страницу и введите код из терминала. Мастер ведёт в настройки IMAP и Яндекс ID. Для работы с почтой с телефона используйте чат личного OpenClaw или совместимый MCP-клиент.
- **OpenClaw с ручной настройкой MCP.** Для ручной регистрации используйте абсолютный путь, который выводит `node ./launch.mjs prepare` в каталоге расширения: `openclaw mcp add yandex-mail --command "/полный/путь/ya-mail" --arg serve`. Для работающего Gateway добавьте `--no-probe` и проверьте список ящиков в новой сессии.
- **Личный HTTPS MCP и n8n.** Задайте в окружении службы секрет `YA_MAIL_MCP_TOKEN` из 43–256 случайных символов base64url. Запустите `ya-mail serve-http --public-origin https://mail-agent.example.org`. Направьте этот HTTPS-хост своим обратным прокси на `127.0.0.1:8775`, сохранив внешний Host. Укажите в credential ноды URL `https://mail-agent.example.org/mcp` и Bearer-ключ. Держатель ключа получает права подключённых ящиков. Интерактивное подтверждение отправки на новый адрес или переноса списка в Корзину проходит в клиенте с формами MCP. [Нода и пример расписания](n8n/README.md)

Поиск поддерживает адреса Cc/Bcc, ограничения по размеру и наличие вложения. Для поиска вложений используется BODYSTRUCTURE. Если IMAP-сервер не принимает произвольную метку, Ya-Ma сохраняет её в локальной базе и включает в поиск. Команда «Измени черновик» возвращает ссылку на новую версию. Для письма в очереди действует обычная правка с остановкой отправки.

## Проверка обновлений

При работающем сервере Ya-Ma в фоне до одного раза в сутки запрашивает последний опубликованный стабильный релиз из GitHub. Запрос содержит только адрес публичного репозитория. При обнаружении более новой версии агент один раз показывает её при просмотре подключённых ящиков. Сбой сети сохраняет доступ к почте и сведения о последней успешной проверке.

```sh
ya-mail updates --check
ya-mail updates --off
ya-mail updates --on
```

Для установки откройте ссылку на релиз. Пользователи автономной Windows-сборки могут распаковать новый ZIP в отдельную папку и выбрать его в клиенте. Для установки через uv завершите ожидающие отправки, закройте клиенты Ya-Ma и переустановите CLI из wheel выбранного релиза. Обновите источник каталога в Codex до того же тега и откройте новый чат. Выбор момента установки остаётся за владельцем.

## Что можно поручить

### Отправка с возможностью передумать

После команды «Отправь» Ya-Ma показывает полный адрес отправителя, поля To, Cc и Bcc, тему, вложения и время отправки. В течение 30 секунд можно сказать «Отмени» или «Поправь письмо». При правке отправка останавливается сразу, а письмо сохраняется в Черновики. Оно останется там до новой команды «Отправь». Эта команда даст ещё 30 секунд. Через «Покажи очередь рабочего ящика» отправку можно найти и из другого чата.

Локальный отправитель продолжает работать после закрытия чата. После сна компьютера или перезапуска отправителя отсчёт начинается заново. При следующем запуске Ya-Ma подхватывает очередь после завершения приложения или перезагрузки компьютера. После передачи SMTP отмена недоступна. При потере ответа сервера Ya-Ma сохраняет Message-ID для проверки в Отправленных и останавливает повторную отправку.

На «Напиши Ивану» плагин ищет имя в выбранном ящике и проверяет заголовки разрешённой системной папки Отправленные за последние 90 дней. При совпадениях показывает два последних адреса с датой и темой. Новый адрес, неоднозначный выбор, похожий домен или смена адресата ответа вызывают форму для сверки перед началом отсчёта. Проверенный псевдоним можно сохранить командой «Запомни адрес Ивана из типографии».

### Удаление и очистка

Попросите, например, «Перемести вчерашние рассылки в Корзину». Даже для одного письма Ya-Ma откроет форму с номером дайджеста, адресом ящика, папкой назначения и количеством писем. У каждой строки указаны исходная папка, UID, корреспондент, дата и тема. Для исходящего письма показан внешний адресат, если он указан в доступных заголовках.

Проверьте список и введите в поле формы фразу с её номером, например **Удалить по дайджесту R-01**. Номера общие для ящиков одной установки. Каждый новый запрос получает следующий номер, в том числе после отмены. Фраза от предыдущего окна не подойдёт. После подтверждения Ya-Ma повторно проверяет выборку. Письма, поступившие за это время, в неё не попадают.

Та же форма защищает перемещение в Спам и Черновики, где возможна последующая очистка, и удаление рекламы из фонового разбора. Для этих действий нужен MCP-клиент, который показывает форму владельцу. Ответ в чате не заменяет ввод в форме.

По команде «Очисти Спам» или по заданному владельцем расписанию плагин окончательно удаляет письма из подтверждённой сервером системной папки. Для Спама подходят письма любого срока, для Удалённых — пробывшие там более 10 суток, для Черновиков — старше 7 суток после последней правки. Можно явно указать другой срок. Когда дата помещения или правки неизвестна, отсчёт идёт с первого наблюдения этого UID в папке. При первой очистке свежеподключённого ящика старые письма могут остаться до следующей проверки. Ожидающие отправки и возвращённые на правку черновики защищены.

### Экономичное чтение и память

Для отдельного локального запуска выполните `ya-mail read "Покажи пять последних входящих рабочего ящика"`. Команда читает каталог Codex, выбирает доступную базовую модель и минимальный поддерживаемый уровень рассуждений. `ya-mail read --show-model` показывает параметры для настройки новой задачи по расписанию. В открытом чате выбор модели принадлежит клиенту.

Для каждого ящика можно выбрать «Выключить обучение», «Только контакты» или «Контакты и факты». Последний режим включён по умолчанию. Список заголовков пополняет контакты, повторное чтение одного письма сохраняет его вес. При чтении выбранного текста агент может сохранить материал заказа, предпочтение или срок с датой, цитатой и ссылкой на источник. Попросите «Что мы знаем о заказах Ивана?», «Исправь этот факт» или «Забудь этот контакт». Смена режима ограничивает сбор и доступ к ранее собранным сведениям.

Команда «Экспортируй память рабочего ящика» вернёт пути к `mail-memory.md` и `mail-memory.jsonl`. Первый файл можно использовать с локальным агентом, второй — самостоятельно импортировать в RAG. При смене правил папок Ya-Ma пересобирает свои файлы. Ранее импортированными копиями управляет владелец RAG.

| Задача | Возможности |
| --- | --- |
| Найти письма | По всем доступным папкам или по выбранной папке. Фильтры по отправителю, получателю To, теме, тексту, Message-ID, датам получения, прочитанности, звёздочке и метке. Страницы внутри папки идут от новых UID к старым. |
| Разобрать переписку | Пакетное чтение, просмотр цепочки по заголовкам References и In-Reply-To, получение продолжения длинного текста. Чтение сохраняет статус непрочитанного письма. Для старой переписки без связывающих заголовков используйте поиск по собеседнику и теме. |
| Получить вложение | Имена, MIME-типы и содержимое по частям. Для полного разбора письма с вложениями действует предел 32 МиБ. |
| Организовать ящик | Папки и счётчики, создание папок, пакетное изменение меток, прочитанности и звёздочек, перенос в архив, спам и корзину. Системные папки определяются по данным сервера. Если нужная роль отсутствует, можно выбрать существующую папку по имени. |
| Подготовить и отправить | Серверные черновики, ответы с сохранением связи по Message-ID, пересылка оригинала как EML, To/Cc/Bcc и файловые вложения. Отправка доступна в режиме с SMTP. Ключ запроса защищает от повторной отправки при повторе вызова. После отправки сохранённого черновика его можно переместить в корзину. |
| Применить метки | В режиме пароля приложения плагин проверяет серверные IMAP keywords и поддерживает локальные метки при ограничениях сервера. Простые имена вроде `orders` передаются напрямую. Для пробелов и кириллицы используется обратимое кодирование. Отображение этих имён в других клиентах зависит от сервера. |

## Вложения из запросов на расчёт и сроки в календаре

1. Подключите почту через `ya-mail connect` и Диск с правом записи через мастер Ya-Di. Попросите агента показать владельца Диска и выбрать существующую папку. Если нужны события, подключите плагин календаря (Ya-Ca в каталоге, проект Ya-Cal) и выберите календарь. Сохранённые файлы наследуют права выбранной папки. [Ya-Di](https://github.com/grebennikovxyz/yandex-disk) · [Ya-Cal](https://github.com/grebennikovxyz/ya-cal-plugin)
2. Задайте ящик, почтовую папку и фразы отбора. Ya-Ma ищет любую из фраз в теме и тексте письма, учитывает кириллицу и считает «е» и «ё» равнозначными. Попросите показать пробный результат на одном письме. Агент вернёт имена файлов и пути назначения.
3. Сохраните правило в локальной задаче Codex, выбрав частоту и время. Свойства правила включают UID владельца Диска из `get_profile`, путь к папке и постоянное имя проверки. Для календаря укажите аккаунт, календарь и правило определения начала и конца события с часовым поясом.

Пример поручения для настройки задачи:

> Каждые 30 минут проверяй новые письма в INBOX ящика orders@example.org. Если в теме или тексте есть «запрос на расчёт» или «просим рассчитать», сохраняй вложения в выбранную папку «Расчёты» моего Диска. Если клиент указал точную дату и время сдачи, поставь в выбранном рабочем календаре событие на 15 минут с этого времени по Москве. При неоднозначном сроке покажи письмо в сводке. Сначала покажи пробный результат.

Инструмент `route_attachments` по умолчанию работает в режиме предпросмотра. При сохранении Ya-Ma передаёт байты библиотеке Ya-Di в памяти. У каждого вложения свой путь, привязанный к письму и номеру MIME-части. При повторе плагин сверяет SHA-256 с файлом на Диске. При смене владельца или конфликте содержимого задача получает ошибку. Предел размера исходного письма составляет 32 МиБ.

Для события Ya-Ma возвращает аргументы `calendar_request`. Агент вызывает `create_event` плагина Ya-Cal с этими аргументами. В описании события будут ссылки на Диск, для открытия которых нужны права на файлы. Ya-Cal проверяет занятость и принимает повторный запрос для того же письма и календаря. При конфликте времени агент сообщает об этом пользователю.

## Запланированные задачи

В настольном ChatGPT с поддержкой локальных плагинов выберите выполнение на этом компьютере. В обычном чате подключите плагин, один раз выполните проверку, затем попросите в этом же чате повторять её в нужное время. Созданная задача появится в разделе **«Запланированное»**. Для запуска оставьте компьютер включённым, а приложение открытым. [Инструкция OpenAI по задачам с плагинами](https://developers.openai.com/training/walkthroughs/scheduled-tasks)

В **локальном Codex** создайте задачу по времени, включите этот плагин и укажите адрес ящика. Запустите первую проверку при настройке, чтобы зафиксировать начальную позицию. Компьютер и системное хранилище пользователя должны быть доступны во время запуска. Пример текста для ежедневной задачи:

> Проверяй входящие ящика orders@example.org. Вызови poll_new для INBOX с именем orders-morning. Прочитай новые письма о заказах, подготовь сводку с отправителями и темами. После обработки всех писем из пакета подтверди его через acknowledge_batch. Если есть продолжение, обработай и его. Сообщи о новых заказах.

Первый вызов начинает наблюдение с текущего конца папки. Чтобы начать с накопленной почты, задайте `include_existing=true` в первом вызове. У каждой комбинации «ящик, папка, имя задачи» своя позиция. Повтор после сбоя вернёт неподтверждённые письма. Для задач с внешними действиями учитывайте возможную повторную обработку. Если IMAP-сервер изменил UIDVALIDITY, плагин остановит чтение этой ленты и сообщит об этом.

Проверка по времени доступна исполнителю, который запускает локальный MCP. Облачная функция ChatGPT Scheduled зависит от доступных в рабочем пространстве приложений. В опубликованном перечне встроенных событий новой почты OpenAI указывает Gmail. Установка этого пакета сама по себе не добавляет Яндекс в список облачных событий. [Расписания ChatGPT](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)

## Хранение данных и отключение

Основной сервер соединяется по TLS с `imap.yandex.ru:993` и `smtp.yandex.ru:465`. Локальная SQLite содержит настройки, позиции расписаний, журнал SMTP, наблюдения о возрасте писем, контакты и сохранённые факты. Отложенные и остановленные письма хранятся в очереди вместе с вложениями до завершения отправки, возврата в черновик или отключения ящика. Для цепочек и точного поиска плагин сохраняет UID и хеши заголовков. Данные в чате обрабатываются клиентом согласно его настройкам.

`ya-mail disconnect адрес@домен` удаляет пароль из локального хранилища и локальные данные этого ящика. Для полного отзыва удалите созданный пароль в Яндекс ID. Если вы пользовались отдельным адаптером 360 в версии 0.5.2, удалите его локальный токен командой `ya-mail disconnect-360` и отзовите старый доступ в Яндекс ID. [Пароли приложений](https://id.yandex.ru/security/app-passwords) · [Доступы к данным](https://id.yandex.ru/profile/access)

### Выпуск в каталогах

1. Выполните `python scripts/marketplaces.py --set-version X.Y.Z`, подставив номер выпуска. Одна команда обновляет проект Python, манифесты Claude Code, Codex и Agent Plugins, пакет n8n и его lock-файл. Оба Git-каталога ссылаются на каталог `plugins/yandex-mail`. Сборка и CI проверяют совпадение версий.
2. После слияния в `main` каталоги Codex, Claude Code и OpenClaw из GitHub уже раздают эту версию. Создайте тег `vX.Y.Z` на проверенном коммите. GitHub Actions соберёт пакеты, опубликует их в GitHub Releases и отправит в ClawHub полный плагин и отдельный навык той же версии. Для ручного обновления источника используйте `codex plugin marketplace upgrade grebennikov-mail` или `claude plugin marketplace update grebennikov-ya-mail`.
3. Для ClawHub один раз добавьте токен издателя как секрет репозитория `CLAWHUB_TOKEN`. Публикация использует личный профиль владельца токена. Имя навыка в каталоге — `ya-ma`, полный пакет — `yandex-mail`. На запросах на слияние CI делает пробную публикацию обоих пакетов. Если реестр задержал проверку или секрет добавлен после выпуска, используйте **Re-run failed jobs** в запуске релизного тега. Сверка проверяет точную версию и содержимое. Текст отдельного навыка предлагается под MIT-0, полный плагин распространяется под Apache-2.0. [Настройка секрета](https://github.com/grebennikovxyz/ya-mail-plugin/settings/secrets/actions) · [Правила ClawHub](https://docs.openclaw.ai/clawhub/publishing)
4. После исправления процесса публикации запустите **Verify plugin → Run workflow** на `main`. Проверенный push в `main` также повторяет синхронизацию, если версия проекта совпадает с текущим стабильным релизом. Публикуются исходники из тега и архив из GitHub Releases после проверки SHA-256.
5. PickAPlugin принимает ссылку на репозиторий и описание письмом, редакция перечитывает публичные источники ежедневно. Для официального каталога OpenAI локальный MCP требует допуска организации к публикации desktop-плагинов. Владелец загружает новый ZIP в портал и публикует одобренную версию после проверки. Windows-архив с окончанием `-windows-x64.zip` содержит локальный runtime. [Заявка в PickAPlugin](https://pickaplugin.com/submit) · [Требования к локальным плагинам](https://developers.openai.com/plugins/deploy/desktop-only) · [Портал OpenAI](https://platform.openai.com/plugins)
